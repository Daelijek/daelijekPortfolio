## Ключевые находки замеров

1. **LCP 12–22 s на mobile вызван картинками, а не JS.**
   - Прелоадер главной ([app/page.jsx:208](../app/page.jsx#L208)) перед показом контента синхронно грузит 6 «критичных» PNG общим весом ~5 MB: `Finance.png` 1.9 MB, `linkedIn_Dias_square.png` 1.4 MB, `berikWeb.png` 848 KB, `roleSieve.png` 642 KB…
   - `/projects` грузит `open-gov-showcase.webp` **3.3 MB**.
   - На `/about` LCP-элемент — фото `linkedIn_Dias_square.png` 1.4 MB.
   - Lighthouse оценивает экономию от современных форматов в **~4.9 MB** только на главной.
2. **Контент главной скрыт за экраном-«воротами»** (выбор Audio ON / Silent, Performance tier, кнопка LOADED). Без клика пользователь и поисковый бот видят только прелоадер (см. `home-*.webp` — сняты уже после клика).
3. **404 на каждой странице** — `/favicon.ico` отсутствует (ошибка в консоли, −Best Practices).
4. **Кэш**: 17 ресурсов с коротким TTL (часть JS-чанков с `max-age=60s`), оценка экономии ~409 KB на повторных визитах.
5. **JS ~850–880 KB** на каждой странице, из них ~276 KB неиспользуемого на главной (в т.ч. весь `portfolioData` на трёх языках).
6. **Читаемость**: на главной только **28.5%** текста имеет legible-размер шрифта на mobile.
7. **A11y 96** на странице кейса: `color-contrast` (недостаточный контраст текста) и `label-content-name-mismatch` (aria-label не совпадает с видимым текстом; на главной то же).
8. **Видимые ошибки контента на скриншоте**: «NEXT.JS 15 / REACT 19», «Next.js 15», «NEXT15_…» в телеметрии — сайт работает на Next 16 (исправляется в Фазе 2).

### Фазы 5–7 — языки в URL, TypeScript, тесты

Замер: Lighthouse mobile, локально, `develop` до фаз и ветка `refactor/i18n-typescript-ci`.

| Страница | Perf | Best Practices | LCP | JS |
|---|---|---|---|---|

- JS −42…45 KB на страницу: словари трёх языков больше не попадают в клиентский бандл.
- Performance и LCP — в пределах шума (±2 / ±0.2 s). Основная причина оставшегося LCP:
  крупные элементы первого экрана (заголовки, фото) появляются через framer-motion с `opacity: 0`
  и видимы только после гидратации. Исправление — убрать анимацию появления у LCP-элементов
  (дизайнерское решение, не сделано без согласования).
- Русская и казахская версии теперь отдаются сервером уже на своём языке (раньше — английский, затем подмена на клиенте).

Desktop (кейсы): Perf 99 → 99, Accessibility **96 → 100**, LCP 0.9 → 0.8–0.9 s, CLS 0.

- **Найдено и исправлено:** `RouteVeil` (затемнение при переходах) сервер отдавал непрозрачным, и до выполнения JS
  каждая страница сайта была закрыта тёмным экраном. Теперь затемнение работает только при переходах на клиенте;
  без JS и до гидратации страница видна сразу. Наблюдаемый LCP кейса: 1015 → 411 ms (LCP = FCP).
- Первый экран кейса (текст, спецификация, обложка) больше не начинает с `opacity: 0` — только сдвиг на место.
- Реальные размеры и размытые превью из `src/content/imageManifest.json`: место под обложку резервируется точно (CLS ≈ 0).
- Симулированный LCP Lighthouse (~4.1 s) почти не меняется: модель Lantern учитывает загрузку и выполнение всего JS
  страницы (~250 KB, общий для сайта код: framer-motion, lenis и т.д.). Дальнейшее улучшение — сокращение общего JS
  сайта, это отдельная задача вне шаблона. Шаблон добавил +6 KB (зум, миниатюры, мобильная панель).
- В Lighthouse CI добавлен кейс с телефонной галереей (`/projects/finance-management-app`).
